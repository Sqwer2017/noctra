# План: прод-интеграция (Render + Vercel + Supabase), Google Auth, фикс стримов

## Что я проверил вживую

- Render жив: `GET /api/health` → `{"ok":true,"tracks":177}`.
- Стрим-эндпоинт работает: отдаёт `application/octet-stream` (аудио).
- **Но** `GET /api/telegram/tracks` возвращает `"streamUrl": "http://localhost:3001/api/telegram/file?..."` — **все 177 треков битые**. Это и есть причина, почему фронт не видит музыку.

**Корень:** `server/index.js:101` — `buildFileUrl()` жёстко возвращает `http://localhost:${PORT}` и **игнорирует `PUBLIC_URL`**. URL запекаются в `server/data/telegram-tracks.json` (310 вхождений) при синке и отдаются клиенту как есть; фронт играет `track.streamUrl` напрямую, ничего не пересобирая.

## 1. Прод-ссылки (критично)

```ts

```

**Клиент:**
- `src/services/telegramTracks.ts` — убрать `localhost:3001`, брать `API_BASE_URL`. Добавить `normalizeStreamUrl()`: заменяет `http://localhost:<port>` на `API_BASE_URL` в пришедших `streamUrl`/`coverUrl`. Это страховка, которая работает даже если Render ещё не задеплоен с фиксом.
- Заменить `VITE_TELEGRAM_SERVER_URL` → `VITE_API_URL` (оставлю обратную совместимость: читаю оба, приоритет новому).

**Сервер (`server/index.js`):**
- `buildFileUrl()` → берёт `PUBLIC_URL` (fallback на `http://localhost:${PORT}` для локалки).
- При загрузке `telegram-tracks.json` — переписывать localhost-URL на актуальный origin, чтобы починить уже сохранённые 177 треков без пересоздания базы.
- CORS: сейчас `origin: true` (отражает любой origin). Заменю на список из `CORS_ORIGINS` + разрешу localhost в деве; `origin: '*'` без credentials оставлю как fallback. Заголовки Range/206/Content-Type уже корректны — проверю и оставлю.
- `/api/stream/:trackId` — **такого роута нет** и он не нужен: реальный роут `GET /api/telegram/file?fileId=`. Не буду плодить дубли; вместо этого в плане явно зафиксирую фактическую схему.

**Деплой-конфиги:**
- `server/package.json` — добавить `"start": "node index.js"` + `engines.node`. Без этого Render с дефолтным `npm start` падает.
- `vercel.json` (новый) — SPA-rewrite, чтобы прямые ссылки не давали 404.
- `.gitignore:16` — опечатка `.server/data` → `server/data`. Сейчас файл с 310 localhost-URL **закоммичен**.
- `.env.example` — обновлю `VITE_API_URL` и поясню про `PUBLIC_URL` на Render.

## Что нужно от тебя

1. **Render → Environment**: `PUBLIC_URL=https://noctra-ffdm.onrender.com` (без него фикс URL не заработает) и `CORS_ORIGINS=https://<твой-домен>.vercel.app`.
2. **Vercel → Environment**: `VITE_API_URL=https://noctra-ffdm.onrender.com`, `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, и `VITE_GOOGLE_CLIENT_ID` (если хочешь One Tap).
3. **Supabase → Auth → Providers → Google**: включить, вставить Client ID/Secret.
4. **Google Cloud Console**: OAuth Client ID (Web) с Authorized JavaScript origins = твой Vercel-домен, и Authorized redirect URI = `https://<project>.supabase.co/auth/v1/callback`.
5. Выполнить `supabase/migrations/001_noctra.sql`, если ещё не выполнил.

## Риски

- **Я не могу задеплоить за тебя** — коммит и пуш делает Render/Vercel сами по вебхуку. Я подготовлю код, ты пушишь.
- `server/data/telegram-tracks.json` закоммичен с localhost-URL. Фикс на сервере перепишет их при старте, так что пересоздавать данные не нужно. Но если хочешь чистоту — можно удалить файл из git и добавить в `.gitignore` (я поправлю правило в любом случае).
- Google One Tap требует валидный Client ID и настроенные origins; при неверной настройке кнопка тихо уйдёт на redirect-фоллбэк — приложение не сломается.
- Без `PUBLIC_URL` на Render фикс URL не сработает, но клиентская страховка (`normalizeStreamUrl`) всё равно починит воспроизведение.
