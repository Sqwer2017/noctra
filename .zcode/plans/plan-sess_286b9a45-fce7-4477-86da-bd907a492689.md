# План: XP, ачивки, лого, One Tap, фикс плеера

## Что я выяснил (всё подтверждено в коде)

### 🔴 Баг №1 и №8: потеря XP — нашёл точную причину

`hydrateFromCloud` перезаписывает локальный XP облачным **безусловно**:
```ts
patch.totalXP = progression.xp ?? 0;   // :363 — затирает без проверки
```
Плюс дебаунс синка **3 секунды** (`SYNC_INTERVAL_MS`, `:143`), а `tickListening` тикает **каждую 1 секунду** — таймер дебаунса сбрасывается на каждом тике и **никогда не срабатывает, пока играет музыка**. Запись уходит только когда музыка встала на 3 секунды.

Отсюда: набрал 23 XP → в базе осталось 16 → перезагрузка → 16 затирает 23.

Ещё 4 сопутствующие дыры:
- `beforeunload` не может дождаться async-записи (браузер закрывает страницу раньше)
- `resetLocal()` при выходе — без финального flush
- `pushProgression` делает `UPDATE` без `.select()` — если строки нет, ошибки не будет, а данные пропадут молча
- `pushListeningStats` идёт мимо `syncWrite` — сбой не ставится в очередь повтора

### 🔴 Баг №5: трек застревает на 0 — нашёл точную причину

У `<audio>` **нет ни одного обработчика ошибок** (`onError`, `onStalled`, `onWaiting`). Цепочка запуска:
```
смена трека → pause() + load() → ждём onCanPlay → play()
```
Если загрузка упала (сеть, 404, CORS) — `onCanPlay` не сработает никогда, `play()` не вызовется, и плеер навсегда встанет на 0:00 без единого сообщения. Плюс:
- `startPlayback` глотает ошибку `play()` пустым `catch {}`
- в `repeat-one` вызов `play()` без `.catch()` — необработанный reject
- `crossOrigin = "anonymous"` ставится в эффекте **после** первого рендера, когда `src` уже начал грузиться — первый трек сессии может падать из-за CORS

## 1. Фикс XP (пункты 1, 8)

**Мержим вместо перезаписи** — как уже сделано для библиотеки:
- `hydrateFromCloud`: брать `max(локальный, облачный)` для накопительных счётчиков (`totalXP`, `totalSecondsListened`, `totalTracksPlayed`), историю объединять по датам. Ничего не теряется.
- Синк **по каждому изменению**: убрать дебаунс-«склейку», которая голодает под тиками. Вместо неё — троттлинг, который **гарантированно срабатывает** (первый вызов сразу, дальше не чаще раза в 3 с, но с обязательным «догоняющим» вызовом). Накопительные метрики уходят сразу, частые тики — троттлятся.
- `flushToCloud` — на `visibilitychange` (`hidden`) вместо `beforeunload`: этот момент браузер даёт корректно обработать. Плюс heartbeat-запись раз в 30 с, пока играет.
- Выход из аккаунта: сначала flush, потом очистка.
- `pushProgression`: добавлю `.select()` — если строка не обновилась, ошибка уйдёт в очередь повтора, а не пропадёт молча.
- `pushListeningStats`: перевести на `syncWrite`, чтобы сбои ретраились.

## 2. Фикс застревания трека (пункт 5)

- Добавить `onError` / `onStalled` / `onWaiting` на `<audio>` с понятным состоянием в UI и авто-переходом к следующему треку при сбое.
- Watchdog: если после смены трека за ~12 с не пошёл `canplay`/`timeupdate` — перезагрузить поток (один повтор), затем перейти дальше.
- `startPlayback`: нормальный `catch` с логированием + один повтор через `load()`.
- `repeat-one`: `play()` с `.catch()`.
- `crossOrigin` выставлять **до** первого рендера — `src` не должен грузиться раньше.
- `load()` вызывать после установки `src` вручную, а не полагаться только на `onCanPlay`.
