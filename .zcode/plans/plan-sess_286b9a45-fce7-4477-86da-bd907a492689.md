## План: фикс вёрстки профиля, квесты, Audius API

### 1. Баннер — фон на всю карточку профиля
Переделать `ProfileHero` по структуре из ТЗ:
- Единый контейнер: `relative w-full rounded-2xl overflow-hidden border border-white/10 p-6 min-h-[300px] flex flex-col justify-between`.
- Слой 1 (`absolute inset-0 z-0`): `<img>` `w-full h-full object-cover object-center` + затемнение `absolute inset-0 bg-gradient-to-t from-black via-black/50 to-black/20`.
- Слой 2 (`relative z-10 flex justify-end gap-2`): кнопки «Редактировать профиль» и «•••».
- Слой 3 (`relative z-10 mt-auto`): аватар с бейджем ранга, ник + галочка, `@handle`, bio, статус, бейдж ранга + XP-полоса.
- Баннер станет фоном всей шапки — без обрезки и «чёрного блока» снизу.

### 2. Центрирование круглых иконок
- Все круглые контейнеры с иконками (галочка верификации, кнопка «!» в квестах, бейджи): базовый класс `inline-flex items-center justify-center shrink-0 aspect-square p-0 leading-none`.
- Внутренним SVG задать явный размер (`w-3.5 h-3.5` внутри `w-5 h-5`, `m-0`), убрать `size={n}` там, где он даёт смещение — либо оставить size, но с `block`/`m-0`.
- Проверю все места: hero-галочка, квестовая «!», DeltaBadge, бейдж ранга, кнопки плеера.

### 3. Фикс обрезания названия ранга
- В `LevelCrest` убрать `truncate`; задать `text-lg sm:text-xl font-bold leading-tight` и `flex-wrap`/перенос на 2 строки (`break-words`).
- То же для строки «Следующий ранг: …» — разрешить перенос вместо обрезки.

### 4. Заголовки квестов
- В карточках квестов оставить **только название** («Погружение», «Коллекционер», «Ночной марафон») — жирнее и крупнее (`text-sm font-bold`), без хвоста «— слушать музыку 30 минут».
- Разделю i18n: `quest.immersion` → «Погружение», и отдельные ключи описаний `quest.desc.*` (уже есть) — полное описание только в модалке «!».

### 5. Интерактивные карточки квестов
- Сетка `grid grid-cols-1 md:grid-cols-3 gap-3` (уже есть).
- **Выполнено**: карточка заливается изумрудным: `border-emerald-500/80 bg-emerald-950/40 shadow-[0_0_25px_rgba(16,185,129,0.35)] animate-pulse`; по центру крупная кнопка **«Выполнено! Забрать»** (светящаяся, зелёная).
- **Анимация клейма (Framer Motion)**: текст кнопки → «Сбор опыта…», поверх карточки вверх взлетают светящиеся `+N XP` (`y:[0,-35], opacity:[1,0], scale:[1,1.25]`), затем карточка → заблокированное состояние с таймером `Доступно через: HH:MM:SS` (до полуночи).
- Сохраню текущую логику стора (`claimQuest`, кулдаун до 00:00), добавлю только визуал/состояние клейма.

### 6. Audius API — новый источник музыки
- Новый сервис `src/services/audius.ts`:
  - `searchAudiusTracks(query)` — ищет треки; ноду получает **авто-выбором**: сначала запрос списка discovery-нод (`https://api.audius.co`), берём первую рабочую, фолбэк — `https://discoveryprovider.audius.co`. Нода кэшируется на сессию.
  - Маппинг в `PlaylistTrack`: `id: audius_<id>`, `title`, `artist`, `duration` (сек → `m:ss`), `coverUrl`, `streamUrl: {node}/v1/tracks/{id}/stream?app_name=NOCTRA_APP`, `source: "Audius"`.
  - Обработка ошибок: при недоступности — бросаем ошибку, UI показывает понятное сообщение и не ломается.
- **Music Search**: добавить табы источников **[Telegram | Audius]**:
  - Telegram — текущее поведение (Load/Sync + серверный статус + фильтр по локальному списку).
  - Audius — поле поиска делает **живой запрос** (по кнопке/Enter, с дебаунсом), показывает результаты; треки сразу играются, свайпаются в очередь, добавляются в избранное и в плейлист (всё уже поддержано `TrackRow` + флоу).
  - Состояния: загрузка, ошибка, пустой результат.
- `types/playlist.ts`: `source` уже включает `"Audius"` — менять не нужно.

### Риски/примечания
- Audius — внешний API: возможны CORS/сетевые сбои. Сделаю авто-выбор ноды + понятную ошибку (как ты выбрал). Если в окружении нет доступа к Audius, поиск покажет ошибку, остальное приложение не пострадает.
- Стрим Audius требует CORS на ноде; если браузер заблокирует — трек не заиграет, но метаданные/поиск будут работать (отмечу в UI, если нужно).
